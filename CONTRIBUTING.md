# CONTRIBUTING.md

## Руководство по вкладу и стилю кода

Этот документ описывает правила оформления кода и стиль комментариев для проекта. Цель — единообразие и понятность: комментарии должны выглядеть так, будто их написал автор проекта.

### Общие принципы
- Код должен быть ясным и компактным. Предпочтительны простые функции с одной ответственностью.
- Убирайте дублирование, выносите повторяющийся код в приватные вспомогательные методы.
- Избегайте избыточных комментариев: комментируем почему, а не что (если код не самодокументируемый).

### Стиль комментариев
- Язык комментариев — русский.
- Комментарии короткие, в первом лице единственного числа или повелительном наклонении (например: "Загружаю студентов", "Скрыть столбец с ID").
- Использую ясные метки для задач: `// TODO:` и `// FIXME:`. После метки кратко указываю причину и приоритет.
- Многострочные комментарии допустимы для сложной логики, но стараюсь их сокращать.

Примеры:
```csharp
// Загружаю список студентов в dataGridView1
private void LoadStudentsToGrid() { ... }

// Скрываю служебный идентификатор
idCol.Visible = false;

// TODO: вернуть поиск по ID, когда добавлю индекс в БД
```

### Именование
- Следую существующей кодовой базе: PascalCase для методов и типов, camelCase для локальных переменных и полей с `_` для приватных полей (`_dbPath`).

### Форматирование
- Соблюдаю `.editorconfig` правила отступов и длины строк. Если `.editorconfig` отсутствует, использую 4 пробела для отступа.

### Рефакторинг комментариев
- При массовой замене комментариев: заменяю длинные/объясняющие формулировки на короткие фразы от первого лица или в императиве.
- Не изменяю семантику кода без явного согласия.

## Процесс внесения изменений
1. Создаю ветку `refactor/comments-and-simplify`.
2. Вношу изменения по файлам или пакетно, оставляю мелкие коммиты с пояснениями.
3. Запрашиваю PR для обзора.

---

Если это соответствует вашему желанию — подтверждайте, и я выполню автоматическую замену комментариев и предложу изменения по рефакторингу исходя из правил выше.
